## The cause Apple did not name

The reviewer reached a **public sign-up form** — while the App Review Notes of this very
submission say *"Accounts are provisioned by each organization's administrator — there is
no public sign-up in the app"*. The claim was false, and it is what put the reviewer on
that screen.

`config/security.php` in SHVIA-WEB argues the opposite of production's state, at length:
the default for `REGISTRATION_OPEN` is **closed**, deliberately, so that *"the insecure
state requires an explicit and traceable act — somebody wrote `REGISTRATION_OPEN=true`
and signed under it"*; closing it does **not** remove onboarding, because admins create
accounts through the API; and anonymous sign-up from the internet was the premise of the
five findings of the c188 pentest. Somebody had opened it.

**This is the third submission in a row where the app and what we told Apple about it
disagreed** — first the microphone (declared hidden while it worked), now the sign-up
(declared absent while it was open). Both were true when written. Neither was re-checked.

## What was measured before changing anything

| Field | Who reads it |
|---|---|
| `birth_date` | **nobody.** Written at sign-up, never consulted. Only functional use: `before:` minus 18 years — an age gate. |
| `phone_ddi/ddd/number` | only `User::712`, which formats it for display. The "SMS alerts" promised on the profile screen have no implementation. |

The columns had been nullable since **11/06**, and that migration says why: accounts
created by an admin never had either, and NOT NULL was breaking those inserts. The
database never needed these fields — only the public sign-up validation did.

## The fix, in two pieces of very different size

**In production, and it took no code.** The login screen already hid the sign-up link
behind `config('security.registration.open')`, and the route was already gated by
`registro-aberto` on GET and POST. So `REGISTRATION_OPEN=false` + `config:cache` removed
the form Apple objected to. Verified from outside on 16/09: `GET /register` answers
**403**, the login page no longer offers the link, `/up` answers 200.

**In the code, for the day sign-up reopens** — [shvia-web#166](https://github.com/samirhvbr/shvia-web/pull/166):
phone optional on both registration doors, date of birth removed, and the 18+ gate kept
as an `age_confirmation` checkbox, because confirming an age does not require storing it
and the guideline allows exactly that.

## Note for whoever reads this next

The Notes now say something true. Before the next submission, **re-read them against the
product** rather than against memory — that is the check that has failed three times
here, and it takes five minutes.
